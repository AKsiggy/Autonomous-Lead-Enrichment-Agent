#Autonomous Company Lead Enrichment Agent

An automated B2B lead enrichment agent that crawls public company websites, extracts relevant business information, and uses an LLM to generate structured company intelligence.

The project uses Selenium, BeautifulSoup, Groq, and Pydantic to provide an end-to-end enrichment pipeline.

Overview

The application follows this workflow:

Company Domain
      ↓
Selenium Web Crawler
      ↓
Internal Page Discovery
      ↓
Text + Email + LinkedIn Extraction
      ↓
Context Builder
      ↓
Groq LLM
      ↓
Pydantic Validation
      ↓
JSON Output


The crawler prioritizes useful business pages such as:

About
Company
Team
Leadership
Contact
Sales
Pricing
Customers
Careers

The extracted content is passed to the LLM, which generates structured company intelligence while minimizing unsupported or fabricated information.

How to Run
1. Install Dependencies
pip install -r requirements.txt

2. Configure Environment Variables

Create a .env file in the project root:

GROQ_API_KEY=your_groq_api_key
GROQ_MODEL=openai/gpt-oss-120b


GROQ_MODEL is optional. If not provided, the application defaults to:

openai/gpt-oss-120b

3. Run with Default Domains
python main.py


The default domains are:

postman.com
supabase.com
vapi.ai


Results are saved to:

output/results.json

4. Run with Custom Domains
python main.py example.com stripe.com notion.so

5. Specify an Output File
python main.py example.com --output output/results.json

Features
JavaScript-capable website crawling using Selenium.
Internal-link discovery and URL prioritization.
Public email extraction from website content.
LinkedIn URL extraction from available website links.
HTML cleanup and text extraction using BeautifulSoup.
Configurable page and context limits to control crawling and LLM input size.
LLM-based company intelligence extraction using Groq.
Structured response validation using Pydantic.
Deterministic LLM generation using temperature=0.
JSON output for easy downstream processing.
Batch processing of multiple company domains.
Error Handling

The application is designed so that a failure for one domain does not stop the entire batch.

The following errors are handled:

Invalid or empty domains.
Browser and page-loading failures.
Website scraping failures.
Groq API request failures.
Empty LLM responses.
Invalid JSON returned by the LLM.
LLM responses that fail Pydantic schema validation.

If a domain fails during enrichment, the error is logged and the pipeline returns None for that domain, allowing the remaining domains to continue processing.

Example:

Domain A → Success
Domain B → Failed
Domain C → Success


Only successfully enriched domains are included in the final JSON output.

Output

The final results are saved as a JSON file:

output/results.json


The output contains the structured CompanyIntelligence data generated by the LLM and validated through the application's Pydantic models.
